# Risk log

Reviewed at each phase exit. Seeded from RC1-638/RC1-646 grooming (2026-11-10).

- **R1 — Author-designed holdout.** The held-out fault families come from a pool the author designed, so "held out" can quietly mean "chosen." Mitigation: freeze rules/prompts/support knowledge first; select the evaluation family by recorded public randomness with source and draw procedure committed before the draw; disclose authorship of the pool regardless. Fallback: author-selected holdout with the narrower claim published.
- **R2 — Self-imposed isolation is easy to cheat.** No-access-to-customer-runtime is a constraint we set ourselves; one convenient peek voids the whole story. Mitigation: isolation is an account boundary with a distinct triage execution identity, and denial is *tested* (the triage identity attempts customer cloud API, DB, shell, telemetry, log, cache, and CI-artifact access and is refused), not asserted.
- **R3 — Headline faults must pass preflight.** The headline is runtime failures that a green preflight did not catch (DB role lacks schema perms; reachable API host, denied upload endpoint; storage writable then unavailable/full). Risk: accidentally building faults preflight would catch, which inflates the result. Obvious preflight failures live in a separate coverage suite.
- **R4 — Error sink dies with the fault.** The storage fault can take out the very sink that records the evidence. The sink must survive injection (independent sink or tested fallback) — added to RC1-646/647 grooming.
- **R5 — Cost blowout.** Per-case lifecycle cost (install, fault injection, bundle, triage, model calls) is unmeasured. Phase 0B measures it against the Phase 0A budget ceiling *before* the evaluation matrix is committed; model cost is provisional until real dev-case Claude calls exist, re-estimated at Phase 5.
- **R6 — Second-environment friction.** A genuinely separate customer environment (second Fly org or new Render account) may hit billing/signup friction that tempts a shortcut back into the vendor org. The account boundary is load-bearing (see R2); record the friction, do not route around it. *Materialized 2026-11-10:* new Fly org requires billing info in the dashboard before machines launch (image build and push worked without it); see spike/log.md.
- **R7 — Artificial product dependencies.** Fault families must come from what ESP actually requires (inventory in docs/phase0/dependency-inventory.md). Adding a dependency just to break it (for example, requiring an extension the schema does not use) fakes coverage.

**RC1-640 exit review (2026-11-12).** R2 held: the install runs entirely under customer identities (operator login, then an app deploy token), and the vendor side only builds and signs. No vendor workflow saw a customer value. R6 recurred in a small way: the convenient identity (the org login) hid that `apps list --org` needs org scope. The deploy-token run surfaced it, so least privilege is tested, not asserted. R3 unchanged: the install ends `installed_not_ready` on ENV-001 until Phase 3 provides a customer Brevo key. New, low: the simulated schema refusal (ADR 0006) stands in for a real breaking migration until ESP ships one.

**RC1-641 exit review (2026-11-12).** R3 held, and the exercise gave live evidence for it: twice `/healthz` stayed 200 while conformance failed (audit INSERT revoked: sign-in 500; destination key disabled: executor 401 before any write), and runtime preflight was green before both. R2 held: conformance ran as the customer operator, inside the customer machine, against the customer's own Brevo key; the key never entered a vendor repo (it briefly sat in the evaluator checkout and was moved by Reid before use). New, medium: **Brevo key reactivation propagates over minutes** (intermittent 401 for about 4 minutes). Phase 6 restores must probe until clean, or the restored case fails for a reason that is not the fault. New, low: conformance leaves two audit rows per run in the customer's append-only log, disclosed in every report.

**RC1-642 exit review (2026-11-13).** R4 is the risk this phase tested, and it held only with a condition. On a full volume ESP's file sink could not write (ENOSPC), and the evidence reached the bundle through the other channel: the `errorevents.sink` storage event on stderr, in the platform buffer. That buffer is about 100 lines, which covered 2.8 s under load, so a storage fault must be bundled promptly. The two channels are complementary, not redundant. The destination 401 reached only the file sink (work run over `fly ssh` never reaches the platform log), and the ENOSPC reached only stderr. R2 held: the collector ran as the customer operator, from the workstation, with an app deploy token and the workspace, and nothing left it except an archive the operator wrote. R3 held again: preflight was green before the startup-failure, family 1, family 2 and family 3 runs. New, low: ESP's sink leaves a partial last line after ENOSPC, which costs one event after recovery (counted as `malformed_json`; ESP follow-up). New, low: `fly ssh` can fail on a Fly API tunnel timeout with the app healthy (seen once); the bundle reports `machine_unreachable`, and install resumes on re-run. Brevo reactivation was clean immediately this time (12 of 12 probes), against about 4 minutes in RC1-641, so restores still probe rather than wait a fixed time.

**RC1-643 exit review (2026-11-13).** R2 held, and the network half is now tested: the triage container reaches only the Claude API and the Datadog intake through a default-deny proxy, and `isolation_test.py` (16 checks, in CI) shows the customer's Fly APIs, app, database host and destination refused, with a positive control so a dead network cannot pass. Triage's only route into the customer environment is a follow-up request a human reads, for a check from a three-entry allowlist the customer-side runner enforces. R1: the registry (rules, facts, prompt, support knowledge, follow-ups) is written from the development cases and ESP's code only, every record carries its digest, and a test keeps held-out-specific terms out of it; the freeze is the digest at the RC1-643 merge commit, and the draw is still RC1-644's. R3 held again: the live demonstration is family 1 after a green preflight, with `/healthz` 200 while conformance failed. R5 re-measured as ADR 0004 required: a triage round costs $0.04 to $0.25, a two-round case about $0.38; the Phase 6 projection is about $7 to $15 of model spend against the $120 ceiling. New, medium: the error-event file is cumulative, so every bundle after the first fault carries old faults; rules that ignored time would diagnose fixed problems, so findings are dated against the current release and conformance windows, and the agent's prompt says the same. New, low: on development cases the rules already name the discriminating follow-up, so the agent's measurable contribution there is choosing to ask; its value where the rules have no knowledge is what the held-out evaluation measures.
